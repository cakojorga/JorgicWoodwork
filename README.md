# Jorgić Woodwork

Marketing website for **Jorgić Woodwork**, a carpentry workshop that makes custom furniture: kitchens, wardrobes, doors, stairs, beds and other joinery.

Live site: https://www.jorgicwoodwork.com

The site content is in Bosnian (`<html lang="bs">`).

## Tech stack

- **Next.js 16** (App Router, Turbopack) + **React 19**, plain JavaScript/JSX
- **CSS Modules** for component styling, global styles in `src/app/globals.css`
- **MUI** (masonry image grid) and **Framer Motion** (animations)
- **Lenis** for smooth scrolling (see [src/utility/smoothScroll.jsx](src/utility/smoothScroll.jsx))
- **Firebase Storage** for gallery images, read on the server
- **Web3Forms** for the contact form
- **Vercel** for hosting, Analytics and Speed Insights

## Getting started

Requires Node.js 20.9+ (needed by Next.js 16).

```bash
npm install
npm run dev       # http://localhost:3000
```

| Script          | What it does                               |
| --------------- | ------------------------------------------ |
| `npm run dev`   | Start the Next.js dev server               |
| `npm run build` | Build for production into `.next/`         |
| `npm run start` | Serve the production build (after `build`) |
| `npm run lint`  | Run ESLint (`eslint-config-next`)          |

## Project structure

```
├── firebase.js                 # Firebase app init; exports `storage`
├── next.config.mjs
├── public/                     # Static files served as-is (favicon, logos)
└── src/
    ├── app/                    # Routes (Next.js App Router)
    │   ├── layout.jsx           # <html>, font, site-wide metadata + structured data, Navbar/Footer
    │   ├── globals.css
    │   ├── page.jsx             # Home
    │   ├── galerija/[slug]/    # Gallery page 1, [page]/ for pages 2+ (static, hourly ISR) + 404s
    │   ├── slike/[...path]/    # Thumbnail proxy: Firebase files served from our domain, CDN-cached
    │   ├── privatnost/, uslovi-koriscenja/
    │   ├── not-found.jsx        # 404
    │   └── sitemap.jsx, robots.jsx
    ├── proxy.jsx                # 308 redirects for old /Galerija/<Title> URLs
    ├── components/             # Navbar, Footer, homepage sections, JsonLd, SmoothScroll, HashScroll
    ├── views/                  # Page bodies used by app/ (GalleryView, Privatnost, UsloviKoriscenja, NotFound)
    ├── lib/                    # Server-side helpers: galleryImages (Firebase), metadata, structuredData
    ├── hooks/                  # useScrollToSection, usePrefersReducedMotion
    ├── utility/                # categories, galleryData (+icons), highlightsData, faqData, site, smoothScroll
    ├── fonts/                  # Inter (static weights, self-hosted via next/font)
    └── assets/highlights/      # Homepage slider photos (WebP, 16:10, 800 + 1600px)
```

Components that use state, effects or Framer Motion start with `"use client"`. Everything is still rendered to HTML on the server first.

## Routes

| Path                          | Page                                                                |
| ----------------------------- | ------------------------------------------------------------------- |
| `/`                           | Home (all main sections), static                                    |
| `/galerija/:slug`             | Gallery for one category, page 1 (static, regenerated hourly)       |
| `/galerija/:slug/:page`       | Pages 2+ of a gallery, e.g. `/galerija/kuhinje/2` (static)          |
| `/slike/<folder>-thumbnails/<file>` | Gallery thumbnails (same files as Firebase, cached on the CDN) |
| `/privatnost`                 | Privacy policy, static                                              |
| `/uslovi-koriscenja`          | Terms of use, static                                                |
| `/sitemap.xml`, `/robots.txt` | Generated by `src/app/sitemap.jsx` and `robots.jsx`                   |
| anything else                 | 404 page (real 404 status)                                          |

Old links are redirected on the server with a permanent (308) redirect:

- `/Galerija/Dnevne%20sobe`, `/Galerija/Kuhinje?page=2` and the old query pagination `/galerija/kuhinje?page=2` (now `/galerija/kuhinje/2`) go through [src/proxy.jsx](src/proxy.jsx).
- Old lowercase slugs listed in `legacySlugs`, such as `/galerija/dnevne-sobe`, are redirected by the gallery page itself.

## Gallery

Gallery categories are defined in one place, [src/utility/categories.jsx](src/utility/categories.jsx), and [galleryData.jsx](src/utility/galleryData.jsx) adds their icons. The navbar dropdown, the About services list, the footer, the sitemap and the structured data are all built from it. Each entry has:

- `slug`: the URL, `/galerija/<slug>` (lowercase, no diacritics, dashes instead of spaces)
- `title` and `description`: shown on the page
- `seoTitle`: the page `<title>` and share title, e.g. "Kuhinje po mjeri u Banjoj Luci"
- `folder`: the Firebase Storage folder
- `legacySlugs` (optional): old slugs that should redirect to this category. Woodwork was earlier called "Dnevne sobe" and then "Retro", so `/galerija/dnevne-sobe` and `/galerija/retro` redirect to `/galerija/woodwork`; "Ostali stolarski radovi" is now Specijalno (`/galerija/ostali-stolarski-radovi` -> `/galerija/specijalno`). Their photos live in the `Woodwork` and `Specijalno` Storage folders (plus `-thumbnails`), the same folders the admin app (jorgicwoodworkupload) uploads to. The old `Dnevne sobe` and `Ostali stolarski radovi` folders are no longer shown on the site.

Images are read from Firebase Storage **on the server** ([src/lib/galleryImages.jsx](src/lib/galleryImages.jsx)), so every gallery page arrives with its photos already in the HTML:

- `<folder>/` holds the full-size images
- `<folder>-thumbnails/` holds thumbnails **with the same file names**. If a thumbnail is missing, the original is used.

The gallery shows 12 images per page. Gallery pages are generated at build time and regenerated at most once an hour (ISR), so newly uploaded photos appear within an hour without a redeploy. Because the pages are static, Next.js prefetches them as soon as a link is on screen, and opening a category is instant.

Photos are delivered like this ([src/lib/galleryImages.jsx](src/lib/galleryImages.jsx)):

- **Thumbnails** go through `/slike/...` ([route](src/app/slike/[...path]/route.jsx)). It's the same file as in Firebase, but the CDN keeps it for 30 days. Firebase takes up to ~1.5 s per image, so without this every gallery visit waited on it.
- **Lightbox photos** (2–3 MB originals) come resized to 1920px WebP from Next.js image optimisation (`/_next/image`, allowed in `next.config.mjs`). If that fails, the lightbox falls back to the original file.

### Adding a new gallery category

1. Upload the images to a new folder in Firebase Storage, and the thumbnails to `<folder>-thumbnails`.
2. Add an entry to `categories` in [src/utility/categories.jsx](src/utility/categories.jsx) and its icon in [galleryData.jsx](src/utility/galleryData.jsx).
3. Optionally add one of its best photos to the homepage slider (see below).

To add photos to an existing category, just upload them to that category's Storage folders. No code change or redeploy is needed, and the sitemap and structured data pick them up automatically.

## Homepage slider ("Izdvojeni radovi")

The slider shows a hand-picked selection of the best work, bundled with the site (not loaded from Firebase). Each slide links to its category. The list is in [src/utility/highlightsData.jsx](src/utility/highlightsData.jsx).

To add a slide:

1. Crop the photo to 16:10 and export two WebP files, `<name>-800.webp` and `<name>-1600.webp`, into `src/assets/highlights/`. Aim for under ~150 KB for the 1600px version.
2. Import both files at the top of `highlightsData.jsx`, add them to the `images` map, and add `highlight("<name>", "<category slug>", "<alt text>")` to the `highlights` array. The alt text describes the photo for screen readers and search engines.

Autoplay changes the slide every 6 seconds. It pauses on hover or keyboard focus, when the slider is off screen, when the tab is in the background, and completely for visitors who have "reduce motion" turned on.

## Smooth scrolling

[Lenis](https://github.com/darkroomengineering/lenis) is started by `SmoothScroll` in the root layout. Use the helpers in [src/utility/smoothScroll.jsx](src/utility/smoothScroll.jsx) instead of calling `scrollIntoView` or `window.scrollTo` directly:

- `scrollToElement(el)` scrolls to a section and leaves room for the sticky navbar. The gap comes from `scroll-margin-top` in `globals.css`.
- `lockScroll()` / `unlockScroll()` must wrap every modal. `overflow: hidden` alone doesn't stop Lenis.
- Inside a scrollable modal, add `data-lenis-prevent` so its own scroll keeps working.

Lenis is disabled for visitors with "reduce motion" turned on; the helpers then fall back to plain, instant scrolling. Links like `/#kontakt` from other pages scroll to that section once the home page loads (`HashScroll`).

## Contact form

[src/components/ContactForm.jsx](src/components/ContactForm.jsx) validates input on the client and posts it to [Web3Forms](https://web3forms.com), which forwards the message by email. The Web3Forms access key is set in that file. A hidden `botcheck` honeypot checkbox catches spam bots: if it is ticked, the form shows the success message but sends nothing.

The form is also protected by **hCaptcha** (`@hcaptcha/react-hcaptcha`, Web3Forms' free shared site key). The widget loads only when the form comes near the screen, the message can't be sent until it is solved, and its token is sent to Web3Forms as `h-captcha-response`. **For Web3Forms to also reject submissions without a valid captcha on its server, enable hCaptcha for this form in the Web3Forms dashboard** (form settings → Spam protection / Block spam → hCaptcha). The CSP in `next.config.mjs` allows `hcaptcha.com`.

## SEO

- **Server-rendered HTML.** Search engines and link previews get the full page, including gallery photos and their alt text, without running JavaScript.
- **Metadata per page** via the Next.js Metadata API: title, description, canonical URL, Open Graph and Twitter cards. Site-wide defaults are in [src/app/layout.jsx](src/app/layout.jsx), and per-page values come from `pageMetadata()` in [src/lib/metadata.jsx](src/lib/metadata.jsx). Gallery pages use one of their own slider photos as the share image.
- **Structured data (schema.org JSON-LD)** in [src/lib/structuredData.jsx](src/lib/structuredData.jsx):
  - `FurnitureStore` and `WebSite` on every page
  - `FAQPage` on the home page, from [faqData.jsx](src/utility/faqData.jsx)
  - `BreadcrumbList` and `ImageGallery` on gallery pages
- **Sitemap** with every gallery photo listed as an image entry (helps Google Images). `robots.txt` points to it.
- **Real status codes:** 404 for unknown pages, marked `noindex`; 308 for old URLs.
- **Pagination:** page 1 is the plain URL and later pages are `/galerija/<slug>/<n>`, each static with its own canonical and title ("… – strana 2").
- **Font:** the same Inter files as before, self-hosted and preloaded by `next/font` instead of loading from rsms.me. They are subset to Latin + Latin Extended (incl. č ć š ž đ), punctuation and arrows: 33 KB per weight instead of 110 KB. If text ever needs other scripts (e.g. Cyrillic), re-subset from the full files at rsms.me/inter.
- **Hero animation** is plain CSS, so the headline is visible as soon as the page paints (good for LCP), without waiting for JavaScript.

`GalleryView` also sets `document.title` itself when the page changes, as a safety net for client-side navigations.

## Deployment

The site is deployed on Vercel. The `production` branch is the live site, and day-to-day work happens on `developer`. Vercel detects Next.js and runs `npm run build`; no `vercel.json` is needed. Make sure the project's **Framework Preset** in Vercel is set to **Next.js**, since it used to be Vite.

## Notes

- Next's CSS minifier (Lightning CSS) adds vendor prefixes itself. Don't write a `-webkit-` copy by hand after the standard property: the minifier then keeps only the prefixed one, which Chrome ignores. This is how the slider arrows briefly lost their blur during the migration.
- For anything that ends up in `className` or other markup, use `usePrefersReducedMotion` instead of Framer's `useReducedMotion`. The latter differs between server and first client render, and React doesn't fix attribute mismatches after hydration.
- The Firebase web config in `firebase.js` and the Web3Forms key are public by design (they ship to the browser anyway). Access is controlled by Firebase Storage security rules and the Web3Forms dashboard settings.
